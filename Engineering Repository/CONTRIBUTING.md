# Contributing to Atlas HDOS

## Before Making Changes

Read `PROJECT_CONSTITUTION.md`.

Then identify:

- The problem being solved
- The expected outcome
- The affected product area
- Any PEOS dependency or shared-platform implication
- The test and acceptance criteria

## Contribution Workflow

1. Confirm scope.
2. Check relevant architecture, sprint, testing, design, security, and release docs.
3. Create or update an ADR for major decisions.
4. Implement the smallest coherent change.
5. Add or update tests.
6. Update documentation when behavior, contracts, or workflows change.
7. Verify against the Definition of Done.

## Codex Session Rule

Every Codex session should begin with:

`Read PROJECT_CONSTITUTION.md before making any changes.`

Codex should preserve the Atlas mission, PEOS boundary, security baseline, testing strategy, and design philosophy in every implementation.
