# Release Plan

## Release Principles

- Every release must map to the Atlas mission.
- Every release must have explicit acceptance criteria.
- Every release must identify PEOS dependencies.
- Every release must include verification notes.

## Release Checklist

- Scope confirmed
- Acceptance criteria written
- Tests updated and passing
- Security considerations reviewed
- Documentation updated
- Known risks documented
- Rollback or recovery path identified
- Release notes prepared

## Versioning

Until a production versioning strategy is approved, use pre-release milestones:

- `v0.1-foundation`
- `v0.2-product-definition`
- `v0.3-technical-foundation`
- `v0.4-mvp`
